ENGINEERING APPROACH

How I work

Most of my work crosses every layer of the stack, from the database migration to the screen that uses it, so I own the contract between them. These are the habits I rely on.

Reproduce it before I fix it

For the gateway header issue I sent a valid token with a forged header using curl, locally and in Docker, before changing any code, then ran the same request after. For team API keys, I recorded the access behaviour before and after the change on the ticket.

Change data in steps that are safe to stop at

Migrations add before they remove, backfill before they narrow, and can run twice without harm. If a rollout stops halfway, nobody is locked out.

Follow the ticket all the way through

Most of my work starts at a database migration and ends in the React screen that uses it. Owning every layer means the contract between them is mine to get right.

Write the rollback down before asking for a merge

For the widget consolidation I wrote the verification gates, a staging smoke test and the exact rollback steps before requesting review.
