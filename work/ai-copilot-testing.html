An AI copilot that tests the workflows it builds

I built the testing loop that lets a workflow-building copilot check its own output, observe execution results, and attempt targeted repairs. The implementation connects Python orchestration with the existing React workflow runner, keeping automated tests aligned with manual execution.

Context and problem

The workflow-building copilot could create or edit nodes, but could not verify them. Testing required a user to manually run a node and feed the result back into the conversation.

Requirements

Let the copilot request a single-node or whole-workflow test; execute through the builder’s established run path; return meaningful status and diagnostic information; support retries without unbounded loops.

My responsibilities

I implemented the backend testing orchestration in Python and connected it to React builder events and node-running behavior. This included test-result normalization, workflow sequence handling, user-facing status, and fixes for special node types.

How the test loop works

The copilot proposes a node or workflow change, requests a test, and pauses. A streaming event prompts the React builder to use the same node runner as a manual Play action. Results return to the copilot, which identifies an appropriate repair target and can request a bounded retry.

Implementation

For node tests, I connected the copilot request to the builder runner, resolved required inputs, collected status and diagnostic output, and sent normalized results back into the copilot session. For whole-workflow tests, the loop proceeds one node at a time and follows the branch actually taken.

Key decisions and tradeoffs

Running tests through the existing UI path reduced discrepancies between AI-triggered and manual behavior. Pausing and resuming across events requires careful state handling, but preserves a single execution contract. Retry limits prevent uncontrolled self-repair loops.

Engineering challenges

Conditional branches require prior node outputs to route correctly. Some generator, transform, and human-intervention nodes could appear successful without meaningful output, requiring more careful status interpretation. UI state and events also had to remain synchronized.

Validation

I validated this manually, through iterative prototypes in the workflow builder; the feature did not have its own automated test suite. Copilot-run tests appeared in the existing run history, so I could compare them side by side with runs launched by hand.

Delivery status

The backend and frontend changes were merged to the development branches.

Outcome

The copilot gained a path to request and inspect node and workflow tests and use the results to guide fixes. It could attempt limited self-repair instead of requiring users to run each test and paste results manually.

Engineering takeaway

AI-generated workflows need feedback from the actual runtime, not only model reasoning. Controlled tool use, explicit execution outcomes, and bounded retries make AI-assisted building easier to validate.
